# tasker — рабочий бэклог (живой)

> Попутный захват идей/дыр, чтобы не держать в голове. Временный дом — позже переносим
> **нодами в сам tasker** (догфуд-роадмап). Не бриф, не канон — черновик, правим свободно.

## Надстройки над нодой (из обсуждения видения)
- **Структурная документация внутри ноды** — идея / концепция / паттерны / пресеты / шаблоны /
  реализация / наброски как **блоки одной ноды** (НЕ дочерние ноды). Сейчас у ноды один сплошной
  `description`. Хотим декомпозицию, чтобы нода не была монолитом.
- **Views ноды** — todo / kanban / roadmap: одни данные, разный интерфейс (как GitHub Projects
  table/board/roadmap). Слой интерфейса, на данные ложится без изменений.
- **Пресеты / блюпринты нод** — «стандарты на узлы, уникальная сборка» (аналогия Unreal blueprints):
  собрать флоу из готовых пресетов, или свой с нуля → сохранить как пресет. Канон:
  knowledger `blueprints/workspace-platform-draft.md` §13.5 + `standards/workflow`. В модели ноды — нет.

## Производные состояния / связи
- **«Blocked» как derived** — узел заблокирован, если есть входящий незакрытый `blocks`/`depends_on`
  (источник не в `done`/`canceled`); отдавать, кто блокирует. Идейно — сестра роллапа. Не построено.
- **Роллап — только прямые дети**, не рекурсивный. Свериться с ожиданием «% готовности всей ветки».
- **Кросс-продукт статус-ивенты** — партнёр получает event при смене статуса (API/websocket).
  Пример: интеграция с чужой веткой (мост = зона девопсера) блокирует наш роадмап. Отложено.

## knowledger (база знаний)
- Сейчас — просто гит-репо `omnifield/knowledger` (`standards/`, `contracts/`, `blueprints/`).
  Ссылаемся на файлы по **URL**. Позже — полноценная база со своим интерфейсом.
- Роадмап только **ссылается** на фундамент/практики, не дублирует их у себя.

## Фронт — дыры из аудита (read-first сейчас)
- Статус узла не виден (показан только rollup-бейдж). Нужен бейдж собственного статуса.
- Нет детального вида ноды (`description` / priority / labels / activity).
- Read-only; наполнение роадмапов — способ не выбран (Go-скрипт / curl / UI).
- Нет верхнеуровневого обзора workspace (счётчики/прогресс/фильтр по статусу).
- N+1 на чтении дерева (перф; на большом дереве квадратично) — бэклог-перф.

## Инфра / view-зависимости (не наша зона, держим в курсе)
- Приложение видно в браузере **только через дверь `:8080`** (single-origin). Дверь — отдельный
  контейнер хаба (hub-core/девопсер); у продукта наружу только внутр. порты (5173/8030).
- После мержа манифеста дверь **регенерит координатор** (publish → regen → reload gateway).
- Фронт-порт (5173) = контракт → запись в `registry/ports.md` делает координатор.

## Dev-заметки
- Локальный dev-proxy `/api/tasker → :8030/tasker` в `web/vite.config.ts` (слот `server.proxy`
  пресета) — чтобы видеть живые данные на `:5173`, пока дверь не в игре. Зеркалит поведение двери
  (снятие `/api`). Dev-only (в build не влияет).
